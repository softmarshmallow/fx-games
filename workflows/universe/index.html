Universe

A poster, a synopsis and a direction in. A reviewed storyworld and one concept image per entity out.

A universe is something to explore rather than play: typed entities, their relationships, the tensions between them and the questions the source leaves open, with exactly one concept image for each entity. It starts from a poster, a synopsis and an expansion direction, and keeps their roles apart: the poster is visual evidence only, and the synopsis holds the world's facts. The world is proposed first, and it must pass an independent review before anything is drawn. Then each admitted entity gets one concept image, reviewed against its record. The set is judged as a whole: a reader who has not seen the synopsis should be able to explain how the world works, who disagrees, and why.

Run it yourself

The committed lantern_ferry world is a complete source: a poster, a synopsis, an expansion direction and the inputs.yaml that names them. Plan it offline, before any spend:

uv run python -m grida.fx plan universe --inputs src/fx_games/workflows/universe/inputs/lantern_ferry/inputs.yaml

The plan prices the world phase exactly and the gallery at its worst case, since how many entities there are is a result of the world. A live run needs --live, an OpenRouter key and a ceiling (--max-usd): with --yes-up-to 1 as well it stops before the gallery once the gallery's price is known, and running it again without that draws the gallery from the admitted world, inside the ceiling, without proposing it again. FX's viewer (uv run python -m grida.fx start --open) shows each entity's image, and the manifest marks the ones its review rejected. The contract holds the source roles, both phases, the judges and the graph.
