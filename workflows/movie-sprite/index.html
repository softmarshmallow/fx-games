Where it works

Works well

  • A finished character picture with a transparent background
  • Gentle idle motion: breathing, a little weight shift, hair and sleeves settling
  • Characters with no green in their design
  • Portrait or landscape takes of three to ten seconds, played back slower if you like

Not expected to work

  • Walking, turning, big gestures, or anything that leaves the pose
  • Green clothing, hair or props: green is what gets removed
  • Exact control of the motion: the prompt guides it, and some takes will not be usable
  • Sound

Good to know

  • The video model may redraw the character slightly. The loop's first frame becomes the new picture for the face workflow.
  • Pick a take before finishing. Finishing is local, so trying other finishing settings costs nothing.
  • MP4 previews have no transparency. Use the lossless loop or the PNG frames in a game.

Run it yourself

The workflow turns a character illustration into a transparent, recurring body animation: draw a take, look at it, then finish it. The finished loop's first frame becomes the canonical picture for the separate portrait-motion workflow. Games decide how to display the resulting videos and images. The contract holds the graph, the call and cache behaviour, and an offline example.

Install the Python dependencies with uv sync --frozen, build the engine with uv run python third_party/fx/tools/build_engine.py (again after each pull), and install ffmpeg and ffprobe on PATH. The command line is uv run python -m grida.fx plan|run movie-sprite; in Python, grida.fx.run("movie-sprite", ...).

Author the take

Put a character PNG with a transparent background beside a take.yaml:

character: character.png
direction: A relaxed listening idle with subtle overlapping movement.
requested_motion:
  - Loose hair ends settle gently; hair roots stay anchored.
  - The forearms and fingers make tiny relaxed adjustments.
  - The chest rises and falls slowly and vertically below fixed shoulders.
constraints:
  - Keep the head, bangs, face, neck and shoulders still.
  - No sideways chest motion, body rocking, external wind or expression change.
seconds: 8
resolution: 720p
aspect_ratio: "9:16"
finish: finish.json

Only character is required. A fixed template and these sections become one video prompt, and the fitted picture is passed as both the first and the last frame; this route has no middle-frame or extra-reference inputs. uv run python -m grida.fx plan movie-sprite --inputs take.yaml shows the steps and the price, offline.

The template holds the head, neck and shoulders still, keeps motion local elsewhere, and asks for a fixed camera, green backing and no sound. Directions can explicitly ask for blinking or mouth movement when separate facial control is unnecessary. Prompts guide generation; they cannot guarantee pixel locks or a useful take.

The original picture supplies identity and pose. A video model may redraw it, including the first frame. After finishing, canonical.png is the exact first frame of the transparent loop; use it for the portrait-motion workflow.

Draw, look, finish

Start with finish.json:

{
  "source_mode": "chroma",
  "playback_seconds": 12,
  "loop_closure": "flow"
}

Draw the take with a spending ceiling:

uv run python -m grida.fx run movie-sprite --inputs take.yaml --live --max-usd 2

The workflow's fx.yaml names fal's Gemini Omni Flash 1.1 image-to-video route. It draws whole seconds from 3 to 10, at 360p, 720p, 1080p or 4k, in 9:16 or 16:9. Credentials use FAL_KEY; see provider configuration. The take is recorded as a job: if the run stops while the clip renders, running the same command again collects it rather than paying for another. python -m grida.fx reroll <run> take asks for a new take on purpose, which the next live run draws, and python -m grida.fx pick <run> take <n> chooses which one is finished.

FX's viewer (python -m grida.fx start) shows the take and the finished loop beside their steps. Change finish.json and run again: the plate, the brief and the take come from the cache, and only finishing runs.

A clip made elsewhere can be finished instead: give footage: selected.mp4 (or a Matroska file with alpha) and no character. That run makes no provider call.

Control the finishing

Finishing applies green chroma extraction, optional fixed regions and local repairs, a bounded optical-flow loop closure, then playback retiming. It preserves native dimensions and source frame count. An eight-second, 192-frame source retimed to twelve seconds still has 192 frames, played at 16 fps; it is not two concatenated loops.

fixed_regions pins caller-selected polygons to the first keyed frame. moving_guards subtracts regions such as loose hair or ears from those pins. The fixed field uses a feather outside its boundary; keep it compact so it does not suppress desired body motion. local_repairs optionally aligns and pins a small opaque attachment. Spatial controls require both source_sha256 and native coordinate_size, preventing geometry for one take from silently affecting another. See the component settings.

source_mode: "rgba" skips chroma extraction. Already finished transparent footage can use source_mode: "finished" with loop_closure: "none" and no spatial corrections; every RGBA pixel is kept. Its endpoint frames must already match. Each frame must include transparent background and fully opaque foreground pixels. Use playback_seconds: null to keep the source playback rate.

Consume the assets

The outputs are listed in the contract. loop.mkv is native lossless FFV1 video with straight RGBA and no audio, and frames.zip adds a numbered PNG sequence when export_frames is true. FFV1 is the lossless interchange master; consumers may select their own playback codec or use the PNG sequence. MP4 previews do not carry transparency. Structural verification checks every decoded native output frame and the loop endpoints. Visual review still chooses whether a new character's motion and keyed edges are acceptable, including over the intended background. That review does not require a game runtime.

For independent eyes and mouth, pass the finished canonical to the portrait-motion workflow, with an inputs file that names it and the committed face spec:

portrait: sprites/idle.png
spec: src/fx_games/workflows/portrait_motion/inputs/face-four-card.json
uv run python -m grida.fx plan portrait-motion --inputs face.yaml

The portrait-motion workflow's input contracts, generation, validation, budgets and outputs are its own. The two workflows exchange an image, not game state or a combined runtime.
