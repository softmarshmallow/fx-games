Giving a finished sprite a blink and a few mouth shapes by hand means cutting out the face, drawing
each state to match the original line work, lining the drawings up, masking them, and checking that
nothing else on the sprite moved. Stage Gen holds that as one graph. A vision model finds the face; an
image model draws every state in one sheet so they match each other; each drawing is aligned to the
original and outlined; a reviewer that did not draw them judges every combination; and the accepted
patches go back on the full sprite with every other pixel left exactly as it was. What comes out is
not a fixed animation: each eye and the mouth is its own patch at one fixed offset, so a game can
blink, wink and talk independently, in any order and at any pace.

## Where it works

<Scope>
  <Works>One finished character image, with or without transparency</Works>
  <Works>Faces with clearly drawn open eyes and a readable mouth</Works>
  <Works>Full-body sprites: the face is found and cropped automatically</Works>
  <Works>Faces large enough that their line work reads at the sprite's own size</Works>
  <Limit>Full lip sync: this run has two mouth shapes, A and O, not a complete set of speech shapes</Limit>
  <Limit>Faces too small to read: enlarging them does not add detail</Limit>
  <Limit>Eyes with hair drawn across them: the outline may be refused</Limit>
  <Limit>Head or body movement: only the eyes and mouth change</Limit>
  <Tip>A result can be partial. If the mouth is refused but the eyes pass, the original mouth stays and the blink still works.</Tip>
  <Tip>The eyes were reviewed as a pair. Winking one eye composes exactly, but was not judged on its own.</Tip>
  <Tip>It reviews still pictures. Watch the animation play before accepting it.</Tip>
  <Tip>Pairs with Movie sprite: use the loop's first frame as the source, and the face states sit on the moving body.</Tip>
</Scope>

## Run it yourself

The workflow takes one finished character image and gives it selectable facial drawings: a half
blink, closed eyes and two mouth shapes, as the spec asks. With a face crop (the default) it finds
the face, draws the states in one sheet on a square crop of it, and returns them at the original
sprite's full size. The source supplies the rest state, all of its transparency, and every pixel
outside the facial patches. It animates drawings on a fixed image; it does not make speech audio,
infer phonemes, move a body or do IK. The [contract](contract.md) holds the graph, what each step
checks, and what a run costs.

### Inputs

An inputs file names the picture and the spec:

```yaml
portrait: character.png
spec: src/stage_gen/workflows/portrait_motion/inputs/face-four-card.json
face_crop: true
```

The picture is a PNG, RGB or RGBA, at most 16383 pixels on a side; a full-body sprite on
transparency is fine. Keep a source whose face reads at its own size: enlarging a small face does
not add detail. The committed `inputs/face-four-card.json` declares a 1024×1024 face workspace and a
sheet of four 512×512 cards: both eyes and the mouth, and an eight-second sample timeline. A face
crop's workspace and grid are square. To animate an opaque portrait whole instead, set
`face_crop: false` and use `inputs/four-card.json`, whose 1024×1536 canvas the picture must match
exactly.

`uv run python src/stage_gen/workflows/portrait_motion/inputs/make_inputs.py DIR` draws an original
geometric character both ways, with the two inputs files, to try the plan with.

### Plan, run, read

```sh
uv run python -m grida.fx plan portrait-motion --inputs face.yaml
uv run python -m grida.fx run portrait-motion --inputs face.yaml --live --max-usd 5
uv run python -m grida.fx inspect portrait-motion
```

The plan prices the run before anything is paid for. The usual accepted run makes five paid calls:
the face box, the feature decision, one sheet edit, the outlines and the still review, about one US
dollar in all. Each answer is held by a judge, and a malformed one is drawn again, six takes at most,
which is why the plan's ceiling is far above a usual run. The structured calls go to
`openai/gpt-6-astra` through OpenRouter, with high reasoning and high image detail, through OpenAI
only; the sheet goes to OpenAI's Sunburst edit route. A project's `gnode.yaml` or `--routes` may
choose another route that serves the step; one that cannot is refused while planning.

Every paid answer is kept in gnode's call cache by the request that made it, so running the same
inputs again pays for nothing, and a run that stopped continues where it stopped.

### Read the result

`outputs/result.json` says what was accepted:

| Status | Meaning |
| --- | --- |
| `complete` | Every requested feature was admitted and passed the still review. |
| `partial` | Some features could not move; they keep their original drawing, and the rest passed. |
| `refused` | A stage refused: `refused_at` names it (face, admission, registration, geometry or quality) and `reason` says why. |

A wide-open mouth may be refused while both eyes give an accepted blink; selecting a mouth state then
keeps the original mouth. An accepted face-crop run delivers `animation.webp`, `states/`,
`patches/` and `manifest.json` under `outputs/`. A patch's RGB already includes its edge blending
and its binary alpha marks the pixels to replace: the manifest says
`patch_application: "replace_selected_rgb_preserve_original_alpha"` and gives `offset_xy`. Keep the
original sprite's alpha, and never resize or blend a patch a second time. The component's
`apply_offset_patch` does exactly that:

```python
import json
from pathlib import Path

from PIL import Image

from stage_gen.components.portrait_motion import apply_offset_patch

outputs = Path("out/runs/portrait-motion/<run>/outputs")
manifest = json.loads((outputs / "manifest.json").read_text())
with Image.open(outputs / "states" / "rest--rest.png") as rest:
    frame = rest.convert("RGBA")
selected = {"eyes": "eyes_closed", "mouth": "rest"}
for item in manifest["patches"]:
    group = "mouth" if item["feature_id"] == "mouth" else "eyes"
    if item["state_id"] == selected[group]:
        with Image.open(outputs / "patches" / f"{item['key']}.png") as patch:
            frame = apply_offset_patch(frame, patch, manifest["offset_xy"])
```

Start each selection from the rest state and apply only that selection's patches. The review judges
still pictures: results keep `temporal_review: "not_performed"` and
`publication_authorized: false`, so watch the animation play before accepting it.
