A universe is something to explore rather than play: typed entities, their relationships, the tensions between them and the questions the source leaves open, with exactly one concept image for each entity. It starts from a poster, a synopsis and an expansion direction, and keeps their roles apart: the poster is visual evidence only, and the synopsis holds the world's facts. The world is proposed first, and it must pass an independent review before anything is drawn. Then each admitted entity gets one concept image, reviewed against its record. The set is judged as a whole: a reader who has not seen the synopsis should be able to explain how the world works, who disagrees, and why.

## Run it yourself

The committed `lantern_ferry` world is a complete source: a poster, a synopsis, an expansion
direction and the `inputs.yaml` that names them. Plan it offline, before any spend:

```sh
uv run python -m grida.fx plan universe --inputs src/stage_gen/workflows/universe/inputs/lantern_ferry/inputs.yaml
```

The plan prices the world phase exactly and the gallery at its ceiling, since how many entities
there are is a result of the world. A live run needs `--live`, an OpenRouter key and a ceiling: with
`--max-usd 1` it stops before the gallery, and running it again with a higher ceiling draws the
gallery from the admitted world without proposing it again. The run's own view shows the gallery,
one card per entity, with a red dot on an image its review rejected. The [contract](contract.md)
holds the source roles, both phases, the judges and the graph.
