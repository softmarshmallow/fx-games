Getting a rigged character from a written idea usually means a day of hand-offs: someone draws a
reference sheet, a mesh service turns it into geometry, a rig service adds a skeleton, and a person
checks each file in Blender before paying for the next step. Stage Gen holds that chain as one
workflow. An agent draws the references, Tripo builds and rigs the mesh, a local Blender worker
checks every hand-off, and a reviewer that did not make the work judges each result at the size a
player sees it. Each stage has a bounded number of takes; if a stage cannot be made good, the run
stops and says why.

## Where it works

<Scope>
  <Works>Adult characters drawn chibi-style, about two and a half heads tall</Works>
  <Works>Short hair that sits close to the head</Works>
  <Works>Hands drawn as closed mittens</Works>
  <Works>Outfits that stay close to the body, such as jumpsuits, jackets and trousers</Works>
  <Works>Games that show the character small on screen, around 120 pixels tall</Works>
  <Limit>Long hair, ponytails and braids: hair is fixed to the head and does not move</Limit>
  <Limit>Animals, and characters carrying weapons, capes, scarves or props</Limit>
  <Limit>Facial expressions, finger movement and cloth that moves on its own</Limit>
  <Limit>Close-up shots: small seams are allowed at the size it is judged</Limit>
  <Tip>The export has a cheer and five test poses. Walk, run and idle come from your own animation library, retargeted onto its skeleton.</Tip>
  <Tip>Skirts where the hands rest often need a second build of the body. That run takes longer and costs more.</Tip>
  <Tip>Needs Blender installed, on macOS or Linux, and your own model and 3D service keys.</Tip>
</Scope>

## Run it yourself

`gnode run character-3d` takes one written character brief, or a character's parts, and returns a
small, textured, rigged character as a GLB with a short set of diagnostic clips, ready for a game
engine to load and drive with its own animations. If a stage cannot be made good within its takes,
the run stops and says why. The [contract](contract.md) holds the exact review, admission, rebuild
and support rules.

The supported profile is short-haired adult SD humans with fixed mitten hands, built whole at the
`low` quality bar. The workflow does not animate faces or hair, does not build animals, weapons or
cloth simulation, and does not author gameplay motion; walk, run and idle clips come from the
consumer.

### Inputs

Write the brief as Markdown, and an inputs file that names it:

```yaml
brief: brief.md
```

Keep the brief original and brand-neutral, name an adult, and describe short hair: long hair and
every other extension are outside the profile. Everything else has a default: `review` (`required`
or `none`), `quality_bar` (`low` or `medium`), `rounds` (takes per reviewed stage, default 2),
`rebuilds` (builds of the body, default 2), `partition` (`whole` or `head_body_hair`) and `through`
(`rig`, or `assembly` to stop before the skeleton). To rig parts you already have, give `parts`
instead of `brief`, one FBX or GLB per part role of the profile.

### Plan, run, read

```sh
uv run python -m grida.fx plan character-3d --inputs inputs.yaml
```

The plan runs nothing paid: it compiles the profile, so a profile or set of parts the character
rules refuse stops here, and it prices every call with the most it may cost. A run then needs
`--live` and a ceiling:

```sh
uv run python -m grida.fx run character-3d --inputs inputs.yaml --live --max-usd 30
```

Every paid answer is kept in the call cache, so running the same inputs again, or resuming a run
that stopped, pays for nothing it already has. The run folder holds `outputs/character.glb`,
`outputs/result.json` (accepted, or delivered unreviewed, with the findings that travel with it),
`outputs/references.png` and `outputs/atlas/`, the labeled pose rows, face strip and torso images
the rig reviewer judged.
`gnode inspect character-3d` shows every step, take and verdict.

### Choosing whether to review

`review: none` skips every independent review and every review-driven take; each stage runs its
producer once. A technically valid character is delivered as `completed_unreviewed`, with its numeric
findings visible and no quality or support claim. Export checks for valid files, skin weights and
appearance still apply.

### The quality bar

`quality_bar: low` means usable in a mobile game at the smallest declared gameplay height, 120 px for
this profile. A defect a player would notice at that size fails; a seam or cuff mark that only shows
when magnified is minor and passes. Texture blocks only when it is scrambled, missing or the wrong
object. `medium` (180 px, a stricter per-boundary policy) exists but is uncalibrated; `high` is
refused while planning.

### When a rig is refused

With review required, a refused rig is not the end of the run. The body is built again from the same
references, with new meshes, a new assembly and a new rig, up to `rebuilds` builds in all; if every
build is refused, the run fails with every verdict on record. A rig the worker cannot bind to the
approved mesh (changed triangle connectivity, drifted geometry or UVs) takes the same path without
paying a reviewer. The most common refusal on this profile is a provider rig that weights a skirt hem
to the mitten hands resting against it; the workflow refuses it rather than repairing weights.

### Support

A run claims support only through a host support record that names exactly its configuration: the
node types, the workflow file, its routes and prices, the Blender build and the settings. Run it with
`python -m stage_gen.workflows.character_3d.support run --record ...`, which checks the record against
the plan before anything is paid for. Without a record a run is development and claims nothing.

### Limits

- One supported configuration: the `whole` partition of the fixed-hand SD human profile at the `low`
  bar. `head_body_hair` and the agent-rigged profiles are experimental.
- No facial animation, hair motion, animals, weapons, cloth simulation or gameplay clips; the six
  clips are diagnostics and a cheer.
- With review required, skirt-to-hand weight bleed from the rig provider is refused, not repaired.
  Skipping review can return an export with this defect.
- macOS or Linux, with Blender installed.
